# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A harness for Claude to play Pokémon Unbound 2.1.1.1 (a CFRU-based FireRed romhack) autonomously. Plan, architecture rationale and phase table live in `docs/research.md`; work is tracked as GitHub issues grouped by phase milestone, and commits/PRs reference the issue number (e.g. `(#8)`).

**Read `docs/learnings.md` before building or playing**, and add an entry whenever something fails or an assumption proves false. Its core rule: vanilla FireRed/CFRU knowledge is a hypothesis on Unbound. Verify with a cheap experiment (RAM diff, walk test, screenshot) before building on it. `docs/gameplay-policy.md` defines how the agent should play (full exploration, every mission, rename every capture, record opponents; the unboundwiki.com corpus may be consulted).

## Running

No build, test suite or linter. Python scripts in `bridge/` are run directly, from inside `bridge/` (they import each other as top-level modules).

- `python bridge/launch.py [STATE]`: start the mGBA dev build (0.11+, needs `--script`; path from the `MGBA` env var) with `probe.lua`, unless an mGBA is already running (it attaches if that one serves 127.0.0.1:8888, else refuses). The build's portable `config.ini` needs `[override.BPRE]` `savetype=FLASH1M` and `hardware=1`. launch.py caps speed at 2x (the user's limit) with mGBA's own limiter (`-C audioSync=1 -C fpsTarget=120`: 120 fps, ~2.4% CPU), normal priority (below-normal starved its display, #144). It starts mGBA **detached through WMI** (`Win32_Process.Create`, parent WmiPrvSE), so it outlives whatever launched it: started from a Claude Code shell, mGBA died with the app when the app auto-updated (#151). Start the runner and the spectator the same way: `python bridge/launch.py --detach NAME [--min] COMMAND...` (e.g. `--detach runner --min cmd /c "python -u agentun.py --workspace D:\ClaudeUnboundRunsull1 --goal-badges 8 >> D:\ClaudeUnboundRunsull1.console.log 2>&1"`). Started inside a disconnected remote desktop session, audio sync never runs a frame, so launch.py waits and retries every 5 minutes rather than run unthrottled. On mGBA 0.10, load `bridge/probe.lua` by hand via Tools → Scripting.
- `python state.py` → state JSON; `python state.py press UP [FRAMES] [SETTLE]` → traced press (before/after snapshot, `moved`, `changed`).
- `python world.py [full]` → collision grid (viewport or whole map) plus NPC/warp/sign/connection lists.
- `python probe.py read32|range|dump|diff|step|press|shot|save|load|autosave ...` → raw bridge access; `dump` + `diff` is the standard way to find new RAM addresses.
- `python tables.py [ROM]` → regenerates `names.json` from the ROM in `rom/`.
- `python bot.py "Bellin Town" "Route 2"` → Phase 1 exit test: scripted walker using only bridge output.
- `python probe.py reload` → load an edited `probe_cmds.lua` into the running mGBA.
- `python ui/server.py [--workspace DIR] [--port 8765] [--bridge-port 8888] [--replay [--speed N]]` → spectator page at http://127.0.0.1:8765/ to keep beside mGBA (#98): reasoning, model router, memory graph, learnings feed, party. It tails the workspace's transcripts, log.jsonl and memory/ (read only) and polls the bridge through `ReadOnlyProbe`, which refuses anything but read8/16/32/range. It never launches mGBA. `--replay` streams a finished or paused run's history; `--mock [SECONDS]` plays a scripted fake run (default 60 s: battles, a catch, all four router handoffs, memory reads/writes, learnings, a badge) with no bridge and a temp memory dir, starting when a page connects; `python ui/test_server.py` checks it offline.

**Everything changes in flight** (user rule): fixes, learning and verification never restart mGBA, reload a savestate mid-run, or restart the agent's session or the runner. Only one mGBA ever runs, the live one on 8888; test without it (a stub Probe, or a fake bridge answering the line protocol on a spare port, plus a stdio MCP client). `launch()` attaches to a running mGBA and refuses to start a second; only an explicit `run.py --fresh` stops one. Set `UNBOUND_PORT` to point `probe.py`/`launch.py` at another port.
- `bridge/*.py`: the MCP server re-imports all bridge modules (itself included) before the next tool call after any of them changes, and appends `HARNESS UPDATED: ...` to that result (`HARNESS UPDATE FAILED: ...` on an import error, keeping the old code). Its runtime state is persisted to `<workspace>/server_state.json` after every call and restored on import (and on a server restart). A changed tool list sends `notifications/tools/list_changed`; Claude Code 2.1.293 honours it (a tool added mid-session was found and called in the same session).
- `agent/CLAUDE.md`: copied into the workspace on the next tool call with `INSTRUCTIONS UPDATED: re-read CLAUDE.md (changed: <sections>)`, and at every chunk start.
- `agent/run.py`: at a chunk boundary the runner re-runs itself as a child with `--reloaded` (continues the session, never `--fresh`, never launches mGBA).
- `probe_cmds.lua`: `reload` (any time, even beside a pending frame command). `probe.lua` itself (socket server, busy bookkeeping, autosave) and mGBA's speed/sync flags still need a manual step: the dev build's Lua API has no fps/sync control, and the core holds the port. Adopting a new core: in the running mGBA, Tools → Scripting, reset the scripting context and load `bridge/probe.lua` (then re-arm autosave: the next runner chunk boundary or `probe.py autosave`).

ROMs, saves and savestates are gitignored and never committed. `rom/` holds the patched ROM; `run/` is the agent's own copy (`Unbound.gba`, `baseline.ss1` fresh-start state, `Unbound.sav`) so it never touches a hand-played save; `saves/` holds autosave backups.

## Testing

Fixes are verified in live play: a fix ships via hot reload and is confirmed on the next real occurrence (a battle-helper change on the next battle), never by restarting the live mGBA or reloading a savestate mid-playthrough. **Only one mGBA may ever run: the live one on port 8888.**

`python tests/regress.py [FILTER]` is an optional safety net, worth running after touching shared helpers or before a fresh run. By default it runs only the offline checks (no emulator, under a second): moves' self-check, harness notes, `press_buttons`, the runner's goal text and bootstrap filtering, and the planner's ledge/gap/stair rules. `--emulator` adds the fixture cases (naming, throw_ball, switch_to, use_item, battle advance_dialog, Grim Woods planner, bridge busy handling) on its own mGBA (port 8890, fixtures from `UNBOUND_FIXTURES`, default `D:\ClaudeUnboundRuns\fixtures`); it refuses to start while any mGBA is running.

## Architecture

Layered per `docs/research.md`: thin, verified state layer + deterministic tools, with the model supplying policy. Phases 0–1 (ground truth, bridge) are what exists; the MCP tool surface and agent loop (Phase 2) are not built yet.

- **`probe.lua`** runs inside mGBA: a line protocol on port 8888, one reply line per command, `err ...` on failure. It is a stable core (socket server, pending/busy bookkeeping, autosave); the commands live in `probe_cmds.lua`, which `reload` swaps in place (a broken file replies `err reload: ...` and the old commands stay). Frame-based commands (`step`, `press`) are pending until done; **only one client may drive the emulator at a time**, and a second client's frame command gets `err busy` (reads and `shot` still go through). After an interrupted run, kill leftover client processes before starting new ones.
- **`mcp_server.py`**: the stdio loop in `serve()` is the only part that never reloads; it dispatches each request to the newest imported `mcp_server` module (see Running for hot reload).
- **`watcher.py`**: harness-run reviewers that never block play. After each action `tick()` may start, in a daemon thread, a `claude -p` call (no tools, no MCP, `--restricted`, short system prompt): a Haiku **watcher** every 10 actions (at most 2 notes or nothing) and a Sonnet **verifier** every 20 (OK or one FIX). Results are delivered by `notes()` on the next action as `WATCHER (step N): ...` / `VERIFIER (as of step N): ...`; `hygiene()` drops a note repeated verbatim within 10 actions (WATCHDOG, VERIFY before answering, FORCED SWITCH, ITEM, MISSED exempt). There is no curator model (dropped in #140: ~11% of a run's cost for housekeeping the agent can do): after each action `guard()` appends any line the agent removed from `memory/` to `memory/archive.md`, copies the operator's hints from `<workspace>/operator.md` into `memory/operator.md` (pinned), and sends a `MEMORY:` note (at most every 25 actions per file) when a file is over budget (objectives 2000 chars, others 8000). Each call is logged to log.jsonl (`harness_call`, model, secs, note, tokens, cost) and usage.jsonl (`kind`), shown in the spectator's router. Queues and busy flags live in a `sys.modules` object that survives hot reload. `UNBOUND_CLAUDE` overrides the CLI path (tests use a fake), `UNBOUND_WATCHER=off` disables it; `python watcher.py` self-checks offline.
- **`probe.py`** `Probe` is the Python client every other module uses. `range` is chunked at 0x1000 to keep reply lines small.
- **`state.py`** holds the verified RAM constants and `get_state()`. Mode (`overworld`/`battle`/`dialog`/`other`) is derived from `gMain.callback2`, `sLockFieldControls` (the only start-menu signal) and text-printer activity, not from `gBattleTypeFlags`, which is never cleared after battle. Party data is CFRU's unencrypted layout; use `gPlayerPartyCount`, not the save block copy. `press()` diffs a small snapshot rather than the screen (weather animates every frame).
- **`world.py`** reads the live map layout (`gBackupMapLayout`, 7-tile border) and metatile behaviors into a grid that accounts for elevation, ledges, water, ice, forced movement and warps; map headers come from an XOR-obfuscated group table in ROM.
- **`tables.py`/`names.json`**: species/move/ability/item/map-section names extracted from the ROM. Unbound has its own ability numbering; each table is checked against known entries so a different ROM fails loudly.
- **`bot.py`**: elevation-aware Dijkstra over the grid, flees wild battles, logs every step, and stops with a screenshot on a stall or an unrecognised screen instead of guessing. `sneak()` (the `sneak_to` tool) walks past trainers' sight lines, including patrollers; the mechanics it handles are listed in `docs/gym-mechanics.md`.

Every RAM/ROM address must be recorded in `docs/addresses.md` with its status (verified / plausible / pending) and evidence. Don't use an unverified address as if it were verified.

Autonomous loops must log each action and have a stall detector, must never press keys blind in an unrecognised state (forced prompts ignore B), and should check the lead Pokémon's HP before entering grass.
